### Additional findings in the changed text

1. **HIGH — Exact-length reads turn normal EOF into a playback error.** If FFmpeg asks for bytes `0–32767` of a 900-byte HLS playlist, the server can validly return `206` with `Content-Range: bytes 0-899/900`. The plan requires exactly the requested bytes and makes anything else an error. That can prevent a valid playlist from opening or discard the last block of a direct-play file. Give ordinary reads an *up to N bytes* result with an explicit EOF. Keep exact-length validation for an HLS `BYTERANGE` that declares a specific extent. [tvos-port.md:262](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:262) · [ipados-port.md:315](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:315) · [RFC 9110 §14.1.2](https://www.rfc-editor.org/rfc/rfc9110#section-14.1.2) · [FFmpeg’s custom reader](https://ffmpeg.org/doxygen/9.0/avio_read_callback_8c-example.html)

2. **HIGH — The TV bridge loses the base URL of a redirected HLS playlist.** If `/start.m3u8` redirects to `/session/42/index.m3u8` containing `part.ts`, Rust knows the final URL. Swift receives only the requested bytes. Resolving against the original URL requests `/part.ts` and can stop playback at the first segment. Define a playlist-open result carrying the effective URL, or have Rust return a distinct, normalized playlist whose references it has already resolved and cleaned. [tvos-port.md:262](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:262) · [ipados-port.md:312](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:312) · [RFC 8216 §4.1](https://www.rfc-editor.org/rfc/rfc8216#section-4.1)

3. **HIGH — The decoder inventory still omits a permitted local video decoder.** The build names dav1d and uavs3d as the permitted external decoders. The pinned FFmpeg also uses external `libxevd` to decode MPEG‑5 EVC, and upstream publishes BSD license terms. On a TV where hardware declines an EVC title, the listed build has no software decoder for Original playback. Derive the dependency inventory from the pinned FFmpeg version, and pin and enable the required libraries, including `libxevd`. [ipados-port.md:481](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:481) · [decisions.md:2797](/Users/michael/Dev/vela/.agents/decisions.md:2797) · [FFmpeg 9.0.2 format support](https://github.com/FFmpeg/FFmpeg/blob/n9.0.2/doc/general_contents.texi) · [XEVD license](https://github.com/mpeg5/xevd/blob/master/COPYING)

4. **HIGH — A log entry is treated as permission to omit a codec.** The plan tells the implementer to list a codec in the Log and disclaim support when its decoder falls outside the licensing rule. AVS2-P2 makes this concrete. The pinned FFmpeg uses `libdavs2`, which requires a GPL build. Following the plan would allow the port to be declared complete while an Original-quality AVS2 title cannot play locally. Keep both owner rulings binding. Provide a license-compatible local decoder, or record the codec as an unresolved implementation blocker. [ipados-port.md:489](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:489) · [decisions.md:2069](/Users/michael/Dev/vela/.agents/decisions.md:2069) · [decisions.md:2797](/Users/michael/Dev/vela/.agents/decisions.md:2797) · [FFmpeg’s davs2 documentation](https://ffmpeg.org/general.html#davs2)

5. **HIGH — Resume can still overwrite newer progress from another device.** The plan compares a checkpoint timestamp from the TV with the server’s last-played timestamp. A TV clock ahead of the server can make its older checkpoint win even after a fresh fetch at Play. Jellyfin also exposes last-played date, playback position and watched state as separate fields, with no documented guarantee that the date versions every change. The fresh session can therefore start at 20 minutes and report over another device’s 50-minute position. Keep the provider state observed alongside the checkpoint and compare it with a fresh read at Play. Honor a changed server position or watched state when ordering is uncertain, preserve an explicit user seek, and use the local checkpoint when the server has no resume state. [ipados-port.md:452](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:452) · [playback.rs:1678](/Users/michael/Dev/vela/src-tauri/src/playback.rs:1678) · [Jellyfin user-item fields](https://typescript-sdk.jellyfin.org/interfaces/generated-client.UserItemDataDto.html)

6. **MEDIUM — A valid move between equal position keys can be impossible to encode.** Suppose A and B both have key `k`, ordered by ID as A then B. The user moves Z between them. Any key below or above `k` puts Z outside the pair. Giving Z the same key puts it after B. Both TVs agree, but both play the wrong order. Specify how to reassign keys across the tied entries under conflict checking, or use position identifiers that can represent an insertion between any two existing positions. [tvos-port.md:386](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:386) · [tvos-port.md:391](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:391)

7. **MEDIUM — Reconnecting with both stores full leaves an online edit with no valid outcome.** A TV can reconnect with its offline journal full while its iCloud account is also out of space. V5 applies only offline, yet the quota rule promises that the next edit stays pending. CloudKit has refused it and the journal has nowhere to retain it. Attempt online edits directly against CloudKit, preserve already-journaled work, and report a new quota-failed edit as unsaved if no durable slot is available. That keeps the failure attributable to actual storage exhaustion. [tvos-port.md:402](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:402) · [tvos-port.md:412](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:412) · [decisions.md:2823](/Users/michael/Dev/vela/.agents/decisions.md:2823) · [CloudKit quota semantics](https://developer.apple.com/documentation/cloudkit/ckerror/code/quotaexceeded)

8. **MEDIUM — The manual redirect loop has no stopping condition.** With `Policy::none`, two endpoints that promptly redirect to each other can keep a media read alive indefinitely. Each connection succeeds, the stall timeout need never fire, and the plan explicitly removes the overall deadline. Playback can hang until the user cancels it. Apply a finite hop limit to each redirect chain and return a media-read error when it is exhausted. [ipados-port.md:306](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:306) · [reqwest redirect policy](https://docs.rs/reqwest/latest/reqwest/redirect/struct.Policy.html)

9. **MEDIUM — Swift owns returned media buffers without a defined way to release them.** If Rust returns a Rust-allocated buffer, the ABI gives Swift ownership but specifies neither a matching release function nor an allocator contract. Guessing the deallocator risks an invalid free. Retaining every buffer leaks memory throughout playback. Let Rust fill caller-provided storage, or return a buffer with an explicit Rust release operation.
