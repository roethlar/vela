## Reopened repairs

- **ipd-32 — reopened · HIGH. Last-played time can select stale progress.** The plan now reconciles on Play, but treats `LastPlayedDate` as the time of the server’s current position. Jellyfin 10.11.0 sets that date on playback start and can save later position updates without advancing it. A TV session started before the iPad checkpoint can reach 50 minutes afterward. The iPad can still choose its 20-minute checkpoint and publish it over the TV’s progress. Keep the server position and watched state observed at checkpoint time. If either has since changed and the provider supplies no reliable revision for that change, use the fresh server state unless the user explicitly sought. - **ipd-36 — reopened · HIGH. The external-decoder list still omits a permitted video decoder.** A-3 presents dav1d and uavs3d as the complete list. MPEG-5 EVC provides a counterexample. The pinned FFmpeg supports the BSD-licensed XEVD library through an explicit build option. On a device without EVC hardware decoding, an agent building the named components leaves Original playback without a decoder. Inventory the pinned FFmpeg release by codec, then pin and enable the required external libraries, including XEVD. - **ipd-52 — reopened · MEDIUM. A delayed close can clear a replacement play.** The repair tracks direct-play cleanup separately, but its criterion for sending a late close is that the request writes no item progress. On Jellyfin 10.11.0, `Stopped` resolves the device session from the authenticated request. The handler clears that session’s current item even when it skips the progress write. If an old close arrives after a fresh `Started` on the same iPad, the new play disappears from Now Playing and its automatic progress tracking stops. Require a close that targets the old play specifically, or serialize cleanup before the replacement starts and suppress later device-wide retries. Also record that Jellyfin’s idle expiry can itself report the old position. ## New findings

1. **HIGH — A Log entry can waive required local playback.** A-3 tells the implementer to list a codec as unsupported when its only available decoder is excluded by the licensing rule. AVS2-P2 illustrates the conflict. FFmpeg documents its external decoder as GPL, while the owner requires both a permitted build and local playback. Following the Log instruction lets the port claim completion with Original playback broken for that codec. Require a permitted local decoder or treat the codec as an unresolved implementation blocker. Only the owner can change the coverage requirement. [ipados-port.md:489](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:489) · [decisions.md:2797](/Users/michael/Dev/vela/.agents/decisions.md:2797) · [FFmpeg AVS2 dependency](https://ffmpeg.org/general.html#davs2)

2. **HIGH — The exact-byte rule turns an ordinary end of file into a read error.** The rule now covers every bounded media read, including the tvOS bridge. For a 1,000-byte resource, a request for bytes `768–1023` can validly receive `206` with `Content-Range: bytes 768-999/1000`. Rejecting that response discards the final 232 bytes. A short playlist can fail on its first read, and a film can end as an error, suppressing playlist advance. Give general media reads a byte count and an explicit EOF result. Keep exact-length enforcement for HLS fragments that declare their length. [ipados-port.md:315](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:315) · [tvos-port.md:262](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:262) · [RFC 9110 byte ranges](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.1.2) · [FFmpeg custom-read example](https://ffmpeg.org/doxygen/9.0/avio_read_callback_8c-example.html)

3. **HIGH — Custom I/O alone cannot enforce the core-only network rule across all enabled demuxers.** A-3 enables every LGPL demuxer. In the pinned FFmpeg, the SDP demuxer can read its header through the supplied `AVIOContext` and then open its RTP transport directly. If a server serves an input that probes as SDP, that operation bypasses the playback client’s network policy. Keep HTTP(S) names registered for HLS and deny native network opens at the FFmpeg protocol boundary. Any supported nested transport must use an explicitly core-backed path. [ipados-port.md:292](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:292) · [ipados-port.md:485](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:485) · [FFmpeg 9.0.2 SDP transport handling](https://github.com/FFmpeg/FFmpeg/blob/n9.0.2/libavformat/rtsp.c#L2435-L2499)

4. **MEDIUM — The prescribed AVS3 build can still exclude 10-bit video.** Pinning and enabling uavs3d with its upstream defaults builds an 8-bit decoder. A 10-bit AVS3-P2 title then fails on the very software path the repair adds. Specify the upstream `COMPILE_10BIT=1` setting in the Apple build and require the shipped configuration to cover both input depths. [ipados-port.md:487](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:487) · [uavs3d Apple build instructions](https://github.com/uavs3/uavs3d#compile)

5. **MEDIUM — Successive range reads can combine different versions of one resource.** The bridge identifies each read by session, URL and range. If a server updates a playlist between two bounded reads, both responses can have numerically correct ranges while their concatenation contains a broken URI or a skipped segment. Give each logical open one stable representation. Snapshot a playlist after resolving and cleaning its references. For media fetched in multiple requests, retain the open response or use a strong validator and restart the read if the representation changes. [ipados-port.md:312](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:312) · [tvos-port.md:262](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:262) · [RFC 9110 on combining partial responses](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7.3)

6. **MEDIUM — Manual redirects have no termination rule.** Two same-origin URLs that redirect to each other pass every origin check. Each response can arrive promptly, so neither the connection nor the stall timeout ends the chain. Playback can remain stuck issuing requests until the user cancels. Cap redirect hops per logical read, detect cycles, and return a credential-free playback error when either limit is reached. [ipados-port.md:306](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:306) · [RFC 9110 redirection guidance](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.4)

7. **MEDIUM — The shared tvOS media bridge transfers a buffer without defining how Swift releases it.** The ABI gives the caller ownership after each read, but lists no matching release operation or allocator. If Rust transfers a Rust allocation, Swift can leak one buffer per read or release it through an incompatible allocator. For a film-length stream, that can exhaust the process or terminate playback. Have Swift supply a destination buffer and capacity, or export a Rust release function paired with the returned allocation. [tvos-port.md:249](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:249) · [tvos-port.md:265](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:265) · [Rust allocator contract](https://doc.rust-lang.org/std/alloc/struct.System.html)
