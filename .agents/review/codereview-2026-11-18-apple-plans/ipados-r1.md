## New defects in the repair text

1. **HIGH — HLS can forward a server credential to another origin.** The repair directs the engine to attach the request headers to *every* child request. An absolute child URI or a redirect can change the scheme, host or port. A second host can then receive the user’s Plex or Jellyfin token even when every URL is credential-free. Vela already pins Plex part URLs to the selected connection origin. Apply that boundary to nested HLS requests and redirects, and verify with two mock origins that only the authorized one receives the header. [ipados-port.md:269](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:269) · [plex_library.rs:2101](/Users/michael/Dev/vela/src-tauri/src/plex_library.rs:2101) · [HLS URI rules](https://www.rfc-editor.org/rfc/rfc8216.html#section-4.1)

2. **HIGH — The new profile 10 promise has no corresponding architecture probe.** On an AV1-capable device, row 16 requires Dolby Vision profile 10. P2 selects the renderer using other profiles, and the fixture recipe generates HEVC. Profile 10 uses AV1 metadata OBUs. Those HEVC tests cannot establish that the chosen route preserves its metadata. This is the new part of ipd-3. Add a validated AV1 Dolby Vision fixture, probe the actual device and minimum OS, and carry the applicable profiles into the iPhone checklist. If a separately bundled dynamic framework calls a required-reason API, Apple requires the declaration in the bundle containing that binary. Identify the calling binaries, package the applicable approved reasons in their respective bundles, and validate those locations in the archive.
