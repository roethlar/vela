## New findings

1. **HIGH — Rejecting a playlist can put its credential in the log.** When the callback refuses a token-bearing child playlist, FFmpeg’s HLS error path logs the playlist URL, query included. The refusal can therefore expose a reusable server credential even when no HTTP request leaves the device. Sanitize playlist references before FFmpeg retains them, and route FFmpeg diagnostics through a sink that suppresses credential-bearing URLs and headers. [iPad plan:282](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:282) · [refusal rule:298](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:298) · [FFmpeg playlist error handling](https://ffmpeg.org/doxygen/9.0/hls_8c_source.html#l02313)

2. **HIGH — Returning before expiry can resume an already stopped session.** The repair moves finalization earlier but keeps the promise that any return before expiry continues the same session. If the server accepts `Stopped` and the user foregrounds the app before the background task expires, that rule resumes a player whose server session or encoder has already ended. Make the start of finalization the cutoff. Once finalization begins, a return must start a fresh session at the saved position. [foreground-return rule:375](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:375) · [early finalization:382](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:382)

3. **HIGH — Replaying an old Plex final position can overwrite newer viewing progress.** If the iPad is terminated and the owner continues the same title on another device, the next iPad launch is directed to finish the old report. Vela’s Plex finalizer writes progress by item key and time. That write carries no precondition tying it to the older play, so it can move the owner’s resume point backwards. Track encoder cleanup separately from progress reporting. Retry the session-specific cleanup and reconcile the saved report with current server activity before writing item progress. [relaunch rule:387](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:387) · [playback.rs:1722](/Users/michael/Dev/vela/src-tauri/src/playback.rs:1722) · [plex_api.rs:14](/Users/michael/Dev/vela/src-tauri/src/plex_api.rs:14)

4. **MEDIUM — Blanket URI refusal breaks playable same-origin transcodes.** If Jellyfin supplies its own `api_key` on the only child playlist, the new rule rejects the stream even though the client already holds the same credential and can authenticate by header. Fixed-quality playback or an Automatic step-down then fails for that item. For a validated same-origin URI carrying the active connection’s credential, remove the recognized credential parameter, preserve the media and session parameters, and use the authorized header. Refuse destinations or credentials that cannot be validated. [iPad plan:295](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:295) · [Jellyfin stream header:169](/Users/michael/Dev/vela/src-tauri/src/source/jellyfin.rs:169) · [Jellyfin URL-credential documentation](https://jellyfin.org/docs/general/post-install/networking/reverse-proxy/#logging)

5. **MEDIUM — Saving every position change consumes the settings rollback history.** The plan emits position at least four times per second and directs the engine to save it in the durable stores as it changes. Using the existing recents store writes the settings document. Each distinct save preserves the previous document and prunes history to three versions. Ordinary playback can therefore replace all three useful settings snapshots with near-identical positions in about a second. Use a separate, coalesced playback checkpoint, flush it on lifecycle transitions, and update normal recents at finalization. [position frequency:238](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:238) · [persistence rule:379](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:379) · [config.rs:757](/Users/michael/Dev/vela/src-tauri/src/config.rs:757) · [durable.rs:689](/Users/michael/Dev/vela/src-tauri/src/durable.rs:689)

6. **MEDIUM — The loopback playlist can misidentify Dolby Vision profile 10.** If P2 uses the HLS fallback for profile 10.1 or 10.4, carrying the metadata OBUs and naming `dav1` is insufficient. Apple requires the AV1 base codec, the Dolby supplemental codec with its compatibility brand, and the matching PQ or HLG video range. FFmpeg 9’s master-playlist writer omits the supplemental-codec and video-range attributes. The resulting playlist can misidentify a valid stream and make a working device route appear unsupported. Generate the loopback master’s attributes from the stream’s actual compatibility ID before drawing a conclusion about device support.
