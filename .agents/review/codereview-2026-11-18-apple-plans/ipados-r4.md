## New design findings

1. **HIGH — The reused HTTP client can forward a provider token across origins.** The plan requires approval of each redirect before following it, yet both ordinary provider clients enable reqwest’s default automatic redirects. On an origin change, the pinned reqwest removes standard authorization and cookie headers but leaves `X-Plex-Token` and `X-Emby-Token` intact. Reusing that client for an authenticated media read can disclose a reusable credential before Vela sees the redirect. Give the playback client `Policy::none()`, validate each `Location`, and build the next request’s headers from its authorized origin. The Plex artwork client already demonstrates the required redirect setting. [ipados-port.md:292](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:292) · [ipados-port.md:306](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:306) · [plex_library.rs:564](/Users/michael/Dev/vela/src-tauri/src/plex_library.rs:564) · [jellyfin.rs:154](/Users/michael/Dev/vela/src-tauri/src/source/jellyfin.rs:154) · [reqwest 0.13.4 header handling:239](/Users/michael/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/reqwest-0.13.4/src/redirect.rs:239)

2. **HIGH — An HTTPS HLS segment can be rejected before the Rust reader is called.** A-3 removes the explicit HTTP(S) build requirement and disables autodetection. FFmpeg 9.0.2’s HLS demuxer looks up the segment URL’s protocol in its compiled registry *before* invoking custom `io_open`. If the build omits HTTPS registration because Rust owns networking, a valid HTTPS transcode fails even though reqwest could fetch it. Require HTTP and HTTPS protocol recognition in the packaged build, keep HLS persistence disabled, and route every actual network read through the core. [ipados-port.md:289](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:289) · [ipados-port.md:303](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:303) · [ipados-port.md:452](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:452) · [FFmpeg 9.0.2 HLS `open_url`](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.0.2/libavformat/hls.c)

3. **MEDIUM — Forwarding a byte range does not establish which bytes came back.** A server may legally ignore `Range` and return `200` with the whole resource. For a nonzero HLS fragment offset, FFmpeg assumes its HTTP reader is already positioned correctly. Passing the response body straight through can repeat an earlier fragment or break decoding. Make the Rust read return the exact requested interval: validate `206 Content-Range`, and handle a full response with bounded slicing or an explicit read failure. [ipados-port.md:294](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:294) · [ipados-port.md:302](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:302) · [HTTP range semantics](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2) · [FFmpeg’s segment offset handling](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n9.0.2/libavformat/hls.c)

4. **MEDIUM — A healthy media transfer can expire after 15 seconds.** Both provider clients impose a 15-second deadline covering connection setup through the end of the response body. A large segment or range that continues delivering bytes past that deadline will be cut off during playback. Give media reads a connection timeout, a stall timeout that resets on progress, and cancellation when the play ends. The existing deadline can continue to govern metadata requests. [ipados-port.md:291](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:291) · [plex_library.rs:564](/Users/michael/Dev/vela/src-tauri/src/plex_library.rs:564) · [jellyfin.rs:154](/Users/michael/Dev/vela/src-tauri/src/source/jellyfin.rs:154) · [reqwest timeout semantics](https://docs.rs/reqwest/latest/reqwest/struct.ClientBuilder.html#method.timeout)

5. **MEDIUM — Interrupted direct play loses its server-session close.** If Jellyfin or Emby accepts `Started` and iPadOS terminates Vela before `Stopped`, the revised recovery rule retries encoder teardown only. A direct play has no encoder, so recovery does nothing and the server can continue showing the item as playing. Track the provider session’s terminal state separately from encoder cleanup and item progress. Use a session-specific close where the provider can preserve newer watch state, and document server expiry where a safe delayed close is unavailable. Simply omitting the offset is unsafe on Jellyfin because it can mark the item completed.
