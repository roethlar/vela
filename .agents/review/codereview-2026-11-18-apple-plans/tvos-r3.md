## Additional design findings

1. **HIGH — An offline edit can be reported saved before it reaches disk.** If the TV loses power immediately after the UI says “saved on this TV,” the only copy of the pending edit may still be in memory. The plan already recognizes this property of `UserDefaults` for connection saves. Give the offline queue a write with a confirmed local persistence result, and show “saved on this TV” only after it succeeds. [Acknowledgment rule](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:369) · [Existing durability caveat](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:299) · [Apple’s `UserDefaults` write semantics](https://developer.apple.com/documentation/foundation/userdefaults)

2. **HIGH — The shipping decoder list excludes files the owner requires to play locally.** A-2 presents software codecs as examples, while A-3 enables *only* the decoders A-2 names. An FFV1 video in an MKV is a concrete counterexample. FFmpeg supports it, but the specified build omits its decoder, leaving an Original-quality play without a local path. Build the permitted software decoder and demuxer set for the full playback requirement, and use hardware support for the actual stream to select the decoding path. [Owner ruling](/Users/michael/Dev/vela/.agents/decisions.md:2796) · [Software path](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:334) · [Build restriction](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:449) · [FFmpeg codec support](https://ffmpeg.org/general.html)

3. **HIGH — A Dolby Vision result can send ordinary video through the wrong renderer.** If P2 finds that Dolby Vision needs loopback HLS, A-2 directs HEVC, H.264, hardware AV1 and VP9 through “the renderer P2 chose.” That includes non-Dolby-Vision VP9, which Apple’s HLS video specification excludes. Route ordinary video through sample buffers. Select loopback only for the Dolby Vision streams that require it. [P2’s decision boundary](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:173) · [Conflicting dispatch rule](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:334) · [Apple HLS video requirements](https://developer.apple.com/streaming/hls-authoring-specification-for-apple-devices.html)

4. **HIGH — The Dolby Vision loopback has no specified lossless audio encoder.** For a Dolby Vision film with TrueHD, the shared audio engine produces LPCM. The loopback now requires ALAC or FLAC, but the package includes decoders and muxers without selecting a lossless encoder. Remuxing cannot produce the required audio track. If loopback is needed, select and ship a local encoding path that preserves channel layout and timing, then mux its output alongside the video. [Loopback requirement](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:180) · [Audio output](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:361) · [Packaged components](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:453)

5. **HIGH — Native media requests can fail for a server the user has configured.** The shared engine now fetches streams through `URLSession`. For an ATS-protected hostname, a user-selected HTTP server or a private certificate rejected by system trust can therefore fail at playback. The plist guidance covers web-view artwork and local networking, and Apple says a `URLSession` delegate cannot loosen trust for an ATS-protected domain. Choose a media transport that implements the supported server settings for user-entered hosts, keeping verification on by default and preserving the origin check on every request. [Transport choice](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:305) · [Plist scope](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:551) · [tvOS certificate setting](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:118) · [Apple’s ATS rules](https://developer.apple.com/documentation/security/preventing-insecure-network-connections)

6. **HIGH — Replaying a Plex checkpoint can still rewind another device.** The repair says to write old progress only if the server has nothing newer. The cited Plex write accepts an item key and position without a revision precondition. If another device saves progress between the TV’s check and its write, the TV overwrites it. Use a conditional write where the provider offers one. Where it cannot establish ordering, retain the local checkpoint and retry session-specific teardown independently of the stale progress write. [Reconciliation rule](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:422) · [Plex write parameters](/Users/michael/Dev/vela/src-tauri/src/plex_api.rs:14)

7. **MEDIUM — Bounded loopback storage leaves long-distance seeking undefined.** On a film longer than the segment retention window, scrubbing back can request an evicted segment, and scrubbing forward can request one the producer has never reached. AVPlayer can seek only to media the local server can supply. Give the loopback a full-title time index and a way to regenerate requested segments from a seekable source within its byte budget. [Seeking claim and producer limits](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:152) · [Siri Remote scrubbing](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:408) · [HLS segment availability](https://www.rfc-editor.org/rfc/rfc8216#section-6.2.1)

8. **MEDIUM — The HLS writer applies backward-compatible Dolby Vision signaling to profile 5.** The new instruction requires `SUPPLEMENTAL-CODECS` with a compatibility brand for the loopback master. Profile 5 has no HDR10-compatible base layer. Advertising one can make a client select a rendition it cannot display correctly. Generate attributes per profile. Apple’s profile-5 example places `dvh1.05…` in `CODECS` with `VIDEO-RANGE=PQ`. Its backward-compatible examples use a base codec and a supplemental Dolby Vision codec and brand. [Writer rule](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:156) · [Profile-5 base layer](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:394) · [Apple’s HLS examples](https://developer.apple.com/streaming/hls-authoring-specification-for-apple-devices.html)

9. **MEDIUM — A bare `AVPlayer` does not take ownership of display matching and Now Playing.** The loopback description attributes both behaviors to `AVPlayer` itself. In Vela’s custom tvOS player, an implementer following that instruction can omit the display-criteria update, leaving the LG in its prior mode, and omit Now Playing publication. Keep display criteria and Now Playing under the custom player’s control on both rendering paths, or explicitly assign them to a system player controller that provides those behaviors. [Loopback claim](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:152) · [tvOS display contract](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:383) · [Apple’s display criteria guidance](https://developer.apple.com/documentation/avfoundation/avdisplaycriteria) · [Apple’s custom-player guidance](https://developer.apple.com/documentation/avfoundation/supporting-remote-interactions-in-tvos)

10. **MEDIUM — Returning to the app has two incompatible session-start rules.** Once finalization begins, the revised text says foregrounding *always* starts a fresh session. The same contract says the view returns paused and starts the session when the user plays again. Following the first instruction can create a server playback session or restart a user-selected transcode merely because Vela came to the foreground. Reconcile the old session on return, restore the paused view, and create the replacement session on Play. [Foreground instruction](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:405) · [Paused-return instruction](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:429)

An implementing agent following that section can block the settings slice on a decision already recorded for all three devices. Point the imported section and remaining gate to the dated O4 ruling.
