## New findings

1. **HIGH — A playlist shared to a second Apple TV can be entirely unplayable.** Link the same server independently on two TVs. Vela assigns a fresh connection UUID on each, and a playlist entry is available only when its source prefix matches a live local source. A playlist created on TV A can therefore appear on TV B with every entry unavailable, even while B is connected to the same server. Persist a portable server, account, and provider-item identity for each backing and artwork issuer. Resolve it to an authorized local connection on each TV. [tvos-port.md:98](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:98) · [commands.rs:440](/Users/michael/Dev/vela/src-tauri/src/commands.rs:440) · [commands.rs:1662](/Users/michael/Dev/vela/src-tauri/src/commands.rs:1662) · [playlists.rs:416](/Users/michael/Dev/vela/src-tauri/src/playlists.rs:416)

2. **HIGH — Pending edits can cross iCloud accounts.** If account A edits offline and account B signs in before upload, V4’s instruction to keep edits until CloudKit is reachable gives the local queue no account owner. Replaying it against the now-current private database can disclose A’s playlist titles or apply A’s changes to B’s data. Bind the cached copy and pending edits to their originating CloudKit account. On an account change, hide that copy and suspend its uploads until the same account returns. [tvos-port.md:101](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:101) · [Apple’s account-change handling](https://developer.apple.com/documentation/cloudkit/cksyncengineaccountchangeevent?changes=la__1_1&language=objc)

3. **HIGH — Two TVs can lose an acknowledged playlist edit.** If two offline TVs append different entries to the same playlist, each starts from the same saved revision. Uploading their local documents in succession can overwrite one append. With CloudKit change checking, the second save can instead remain in conflict indefinitely. The desktop’s process-local lock cannot serialize two devices. Preserve stable entry and operation IDs, merge independent edits against the server revision, and define how conflicting moves and deletes are resolved. [tvos-port.md:98](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:98) · [tvos-port.md:315](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:315) · [playlists.rs:46](/Users/michael/Dev/vela/src-tauri/src/playlists.rs:46) · [CloudKit conflict handling](https://developer.apple.com/documentation/cloudkit/ckerror/serverrecordchanged?changes=l_3)

4. **HIGH — Continue Playing can start an unrelated title in the default mode.** The repair directs Home to choose from the carousel whenever it receives `continue-playing`. The desktop uses that rule only for `on`. The default `only-tv` asks for the next episode in series order and stops after a movie or the final episode. `off` stops immediately. Following the repaired instruction literally can autoplay an unrelated movie even with continuation disabled. Keep the screen as caller and preserve all three branches, including the completed-session check. Put the container configuration in the tracked XcodeGen project, include it in provisioning, and make deployment of the corresponding production schema a prerequisite for the TestFlight build that uses it. 6. **MEDIUM — An offline launch cannot always show the last playlist copy.** This fails even with no pending edits. If a previously downloaded library exceeds the local persistent space and tvOS purges the cached copy, an offline launch has nowhere to read it from. Showing an empty, editable library would misrepresent the account’s saved playlists. Specify an explicit *last copy unavailable offline* state, preserve any pending edits separately, and reload the account’s library when connectivity returns. [tvos-port.md:103](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:103) · [tvos-port.md:129](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:129) · [Apple’s tvOS storage guide](https://developer.apple.com/library/archive/documentation/General/Conceptual/AppleTV_PG/iCloudStorage.html)

7. **MEDIUM — CloudKit can refuse a save while the TV is online.** V4 promises playlists have “no size limit.” A private database consumes the owner’s iCloud quota, and CloudKit also limits individual records. A full account or an oversized playlist stored as one record can leave a healthy edit permanently pending. Use bounded entry records, surface quota failures, and distinguish an edit saved on this TV from one accepted by CloudKit. [tvos-port.md:98](/Users/michael/Dev/vela/.agents/plans/tvos-port.md:98) · [Apple’s private-database quota error](https://developer.apple.com/documentation/cloudkit/ckerror/quotaexceeded?language=objc) · [CloudKit record limits](https://developer.apple.com/library/archive/documentation/General/Conceptual/iCloudDesignGuide/DesigningforCloudKit/DesigningforCloudKit.html)

8. **MEDIUM — The eARC-only rule excludes a supported soundbar connection.** V1 says multichannel PCM and Dolby MAT reach a soundbar only over eARC, then lists direct Apple TV-to-soundbar HDMI as a possible owner setup. On that direct connection, audio reaches the soundbar before video reaches the TV. Applying the eARC requirement would reject a working Atmos route and misstate the owner’s playback capability. Distinguish direct HDMI input from the TV’s ARC or eARC return path, then record what the soundbar receives on that route.
