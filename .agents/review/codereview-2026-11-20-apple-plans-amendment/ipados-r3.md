## Additional findings

1. **MEDIUM — A validator-free MP4 can fail before its first picture.** When `moov` follows `mdat`, FFmpeg must read the index at the end and seek back to the first sample. A new forward-only demuxer repeats the same sequence. I checked the retained `snow-fades.mp4` with FFprobe 9.0.2. The seekable file yielded a packet at `0.000000`. The same bytes through a forward-only pipe yielded `offset 0x2c: partial file` and no packet. Give the demuxer seekable access to a local snapshot of one complete response. That preserves representation identity and supports internal seeks during startup. [Plan line 392](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:392) · [FFmpeg MOV sample read](/Users/michael/Dev/vela-agent-keep/apple-probes/p2/ffmpeg/ffmpeg-9.0.2/libavformat/mov.c:11821)

2. **MEDIUM — A timestamp reset rewinds reported progress.** After a source resets to zero at item time 60, an offset of +60 correctly schedules source timestamp 5 at item time 65. The instruction to compute the reported position back through that offset sends 5 to the page and server. The progress bar jumps backward and the saved resume point can be a minute early. Report elapsed item time and use the per-segment offset only to translate packet timestamps and seek coordinates. [Plan line 683](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:683) · [FFmpeg’s segment-duration mapping](/Users/michael/Dev/vela-agent-keep/apple-probes/p2/ffmpeg/ffmpeg-9.0.2/libavformat/hls.c:2047)

3. **MEDIUM — A changed redirect target can splice two resources with matching ETags.** If one request resolves to `/a` and a later one to `/b`, both resources may legally use the strong ETag `"1"` for different bytes. The repaired `200` rule accepts the second body as unchanged and feeds its interval to the first demuxer. Bind the validator to the final effective resource URI and restart the logical open when that identity changes.
