### Reopened

- **ipd-61 · `14a6960` — Aligned picture dimensions still understate some allocations.** The repair puts the reservation before decode and reconciles it afterward. The remaining problem is the size reserved. FFmpeg 9.0.2’s dav1d allocator rounds width and height to 128 pixels, computes the aligned image size, then allocates **two additional alignment units**. A phone with exactly the calculated image size left in its budget will admit that decode and cross its limit before reconciliation. Reserve the allocator’s full byte requirement for software pictures and establish a conservative backing-size bound for each VideoToolbox pool before admitting its output. - **iph-29 · `4250781` — A valid shorter `206` can still interrupt HLS playback.** The repair handles the round-two example in which bytes `0–1023` arrive first. For the same request for `0–2047`, RFC 9110 also permits the server to send the subset `1024–2047` first. The plan requires every `206` to start at the requested offset, so it rejects that response even with the same strong ETag and a complete resource. Validate the returned interval, request the missing prefix under the same validator, and deliver contiguous bytes to FFmpeg in order. ### New findings in the repaired text

- **HIGH — The software fallback ends playback for a locally decodable title.** On an iPhone without hardware AV1 decoding, a valid profile 10.0 stream reaches dav1d. The repaired rule ends the play because the base picture needs Dolby’s mapping. That prevents incorrect colours, but also leaves the title unplayable despite the owner’s local-playback ruling. Keep the explicit error as an interim safeguard and design a local path that applies the parsed per-frame mapping to produce correctly tagged HDR output. FFmpeg documents this conversion to BT.2020/PQ. - **MEDIUM — The pinned MP4 demuxer leaves `dav1` tracks without an AV1 codec ID.** This can prevent a profile 10 MP4 from reaching VideoToolbox even on an AV1-capable iPhone. In an in-memory container probe, FFprobe 9.0.2 read the profile 10 configuration with either sample entry. It reported `codec_name=av1` for `av01` and omitted the codec name for `dav1`. The pinned MOV tag table confirms the missing mapping. Recognize the registered `dav1` entry as AV1 at demux, preserving its Dolby configuration and metadata OBUs for the decoder.
