### New findings in the repaired text

- **MEDIUM — An HLS server can legally return a shorter `206`.** For a combined request covering bytes `0–2047`, a server can return `Content-Range: bytes 0-1023/2048` with a strong ETag and serve the remainder on the next request. The repaired rule requires the whole requested extent to come back and treats anything else as a read error. That can interrupt playback of a complete, unchanged resource. Validate each response against its declared `Content-Range`, request the contiguous remainder under the same validator, and enforce completeness across the logical FFmpeg open. [Head transport rule](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:362) · [RFC 9110 §15.3.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7)
- **MEDIUM — The profile 10 software path asks dav1d for raw RPU bytes it does not return.** On an AV1-capable phone where VideoToolbox refuses a particular profile 10 stream, A-2 routes decoding to dav1d and directs the engine to attach the raw RPU supplied with the frame. FFmpeg 9.0.2’s dav1d path supplies parsed `AV_FRAME_DATA_DOVI_METADATA`. Code looking for `AV_FRAME_DATA_DOVI_RPU_BUFFER` will find no payload to hand off, preventing the promised Dolby Vision presentation. Specify the profile 10 handoff separately, preserving the source metadata OBU with its matching displayed frame or consuming the parsed metadata through a supported presentation path.
