## Additional findings

1. **MEDIUM — An unchanged file can repeatedly restart on seek.** The repaired range rule treats every `200` after `If-Range` as proof of replacement. HTTP allows a server to ignore `Range` and return the complete, unchanged file. On a server that does this consistently, a demuxer seeking to a nonzero offset can restart on every attempt and never reach that offset. When the `200` carries the same strong validator, retain the response and serve the requested interval from it. Restart when identity changed or cannot be established. [Plan line 379](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:379) · [RFC 9110 §14.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)

2. **MEDIUM — The profile 10 software path asks dav1d for metadata it does not return.** The software handoff assumes FFmpeg supplies raw RPU bytes beside each decoded frame. That holds for the pinned HEVC decoder. For AV1, FFmpeg’s dav1d wrapper parses the Dolby metadata and attaches `AV_FRAME_DATA_DOVI_METADATA`. If a profile 10 stream reaches dav1d, the specified lookup for `AV_FRAME_DATA_DOVI_RPU_BUFFER` yields no payload to present. Make the handoff codec-specific, retaining and associating the original AV1 metadata OBU with its output picture, and gate Dolby Vision presentation on a supported handoff. [Software rule](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:443) · [Profile 10 design](/Users/michael/Dev/vela/.agents/plans/ipados-port.md:554) · [dav1d wrapper](/Users/michael/Dev/vela-agent-keep/apple-probes/p2/ffmpeg/ffmpeg-9.0.2/libavcodec/libdav1d.c:355) · [Emitted frame data](/Users/michael/Dev/vela-agent-keep/apple-probes/p2/ffmpeg/ffmpeg-9.0.2/libavcodec/itut35.c:357)
