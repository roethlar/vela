# fr-11: a report's failure is logged with whatever the server put in its status line

**Severity**: MEDIUM — A report's failure is logged with whatever the server put in its status line.
**Status**: Verified — codex wrote the repair; reviewed by the working agent, 2026-11-16
**Branch**: —
**Commit**: `9d05964`

## Evidence

Reviewer, verbatim: "src-tauri/src/playback.rs:1469 removes the error's URL, but the new final-timeline logger at line 1557 formats the entire error. A local probe through update_timeline returned 'HTTP/1.1 400 rejected http://server/report?token=synthetic-secret' and produced 'plex: final timeline update failed: HTTP status client error (400 rejected http://server/report?token=synthetic-secret)' despite error.url() being None."

## Predicted observable failure

Reviewer, verbatim: "A server or proxy that echoes a URL or credential in its reason phrase exposes it in stderr. The formerly silent final-timeline failure now introduces this logging path."

Reviewer's suggested direction, verbatim: "Log a controlled error category and numeric HTTP status. Avoid formatting server-supplied reason phrases or arbitrary error chains."

## What

Admitted on the reviewer's probe: `without_url()` removes the URL reqwest
attaches to an error, but the error's text for an HTTP status includes the
reason phrase the server sent, and the log line for Plex's final timeline
failure (new in e50aa83; the failure used to be dropped silently) prints the
whole error. A server or proxy that echoes the request's URL or a token in
its status line would put it in Vela's log. Unlikely, and exactly what the
repository's rule on credentials in logs exists for.

## Approach

What landed (`9d05964`), in its commit's words:

A report that failed was logged with reqwest's error after its URL had
been taken off. For an HTTP status that text still carries the reason
phrase the server sent, and a server or proxy that echoes the request's
URL there would have put a token into Vela's log; e50aa83 had added such
a line where a failure used to be dropped silently (review finding
fr-11).

Reports now fail with an error of their own that holds only what kind of
failure it was (a status, a timeout, a failure to connect, and so on)
and, for a status, its number. The original error is not kept, so
nothing a server supplied can reach a log line by any route. What is
retried is decided before the error is reduced, and is unchanged.

A log line that read "error sending request" with the transport's detail
now reads "connection error" or "HTTP status 503".

Written by codex; reviewed by the working agent. Two tests send every
kind of report of both trackers to a server whose status line carries a
URL with a token, first try and retried, and look at what would be
logged: with the product hunks of this commit taken back, both fail;
with them, both pass.
