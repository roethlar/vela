# eh-12: Mock Jellyfin ignores the query contract — client regressions pass silently

**Severity**: MEDIUM — the mock leg's value is contract fidelity; an ignore-all Items route lets ParentId/IncludeItemTypes regressions stay green against the mock while breaking against real Jellyfin
**Status**: Open
**Branch**: n/a — no-branches adaptation; fix lands as a single commit on `main`
**Commit**: (filled in after commit)

## Evidence
`tests/e2e/mockjf.mjs` (pre-fix) records only `pathname` and serves the
movie for ANY `/Users/u1/Items` request. The real client sends `ParentId`,
`IncludeItemTypes`, pagination, and sort
(`src-tauri/src/source/jellyfin.rs:833-848`). Filed by codex in the e2e-7
batch pass.

## Predicted observable failure
A regression that passes a namespaced section key as `ParentId`
(`jf-mock:lib1`), drops `ParentId`, or loses `IncludeItemTypes=Movie`
still gets `Mock Movie` from the mock and the scenario passes — while a
real Jellyfin library would return wrong contents, nothing, or an error
before mark-watched is even reachable.

## What
The mock validates the path but not the query, so it proves less of the
client contract than it appears to.

## Approach
The mock parses the URL once, records `searchParams`, and the Items route
fails closed (400 + a `contractViolations` entry) unless `ParentId=lib1`
and `IncludeItemTypes` containing `Movie` are present; the scenario
asserts zero recorded contract violations at the end.

## Files changed
- `tests/e2e/mockjf.mjs` — query recording + Items contract validation
- `tests/e2e/scenarios/markwatched.mjs` — zero-violations assertion

## Guard proof
Deterministic red/green: with the mock's expected `ParentId` temporarily
set to a wrong value, the scenario must FAIL at the movie-card wait (the
mock 400s the browse); with the true contract expected, it must PASS.
Executed results transcribed below.
