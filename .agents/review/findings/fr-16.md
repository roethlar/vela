# fr-16: the guard of the page's mount target accepted `data-id="app"`

**Severity**: LOW — The guard of the page's mount target accepted `data-id="app"`.
**Status**: Verified — codex wrote the repair; reviewed by the working agent, 2026-11-16
**Branch**: `remove-sveltekit` (merged at `dee0f8b`)
**Commit**: `1dc3f62`

## Evidence

Reviewer, verbatim: "tests/frontend-shell.test.mjs:54 uses /\bid\s*=/, which also matches data-id. Replacing index.html's id="app" with data-id="app" left all four shell tests and npm run build passing. The mutation was restored."

## Predicted observable failure

Reviewer, verbatim: "The guard falsely accepts a missing mount target. With that mutation, src/main.ts:6-7 throws because getElementById("app") returns null, leaving the app blank. Severity is LOW because this is a demonstrated validation gap; the checked-in markup is correct."

Reviewer's suggested direction, verbatim: "Count actual HTML id attributes rather than matching attribute-name suffixes. Add a regression case proving that data-id="app" cannot satisfy S4."

## What

Admitted. S4 of `tests/frontend-shell.test.mjs` is the test that keeps
`index.html` and `src/main.ts` in agreement about where the app is mounted.
It looked for the target with an expression that matched any attribute
ending in `id`. The checked-in page was right; the guard would not have
caught it going wrong.

## Approach

What landed (`1dc3f62`), in its commit's words:

S4 of tests/frontend-shell.test.mjs holds that index.html has exactly
one element with the id `app`, the one src/main.ts mounts into. It
looked for it with an expression that matched any attribute ending in
`id`: with index.html's id="app" replaced by data-id="app", all four
shell tests and the build passed, and the app would have started blank
(review finding fr-16, from the hunt over the SvelteKit removal).

The check now parses the page and looks at whole attribute names: one
element whose `id` is exactly `app`, inside the body. Text that only
looks like it does not count (another attribute's name or value, a
comment, the contents of a script, style or template), and a real id
written with other quoting or spacing still does. 56 small pages hold
those cases.

Written by codex, which ran every case against the old expression (39
of them came out wrong) and the new one (none). Reviewed by the working
agent, who made the reviewer's change to the real index.html again: S4
now fails on it.

Tests only.
