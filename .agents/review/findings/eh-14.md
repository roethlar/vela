# eh-14: Merged-view override assertion accepts any key/value

**Severity**: LOW — a wrong-key or wrong-source persist would keep the scenario green while the user's backing choice silently fails to win ranking later
**Status**: Open
**Branch**: n/a — no-branches adaptation; fix lands as a single commit on `main`
**Commit**: (filled in after commit)

## Evidence
`tests/e2e/scenarios/mergedview.mjs` (pre-fix) polls only
`Object.keys(cfg.merged_overrides).length > 0`. The UI persists
`canonicalId → sourceId` and the backend applies overrides by exact
canonical key (`src-tauri/src/commands.rs:2136`, applied at 2093-2098;
key shape from `canonical_id_of`: `title:mockmovie|2020` for this seed).
Filed by codex in the e2e-9 batch pass.

## Predicted observable failure
A regression writing the override under a wrong canonical key or with the
wrong source id still yields a non-empty map — scenario green — while on
relisting/restart the persisted choice never wins ranking and a plain
Play opens the default backing instead of the chosen one.

## What
The guard proves persistence-of-something, not persistence of the right
mapping.

## Approach
Assert the exact entry: `merged_overrides['title:mockmovie|2020'] ===
'local'` after choosing the local backing, and poll for it flipping to
`'jf-mock'` after choosing the server backing — covering both the key and
the value through a full override flip.

## Files changed
- `tests/e2e/scenarios/mergedview.mjs` — exact-key/value assertions, both
  directions

## Guard proof
Deterministic red/green: with the expected key temporarily set to a wrong
canonical (`title:wrong|2020`), the poll must time out and FAIL; with the
true key, both directions PASS. Executed 2026-07-05: red — with `title:wrong|2020` expected, the poll
times out (`timed out waiting for the override to persist as
title:wrong|2020 → local`, exit 1); green — the true key passes in both
directions (`→ local`, then flipping `→ jf-mock` after the server-backing
choice).
