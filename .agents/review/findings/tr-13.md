# tr-13: Plex universal-transcode query builders can drift

**Severity**: LOW — a future parameter change can make the capability decision
describe a different delivery from the URL Vela starts.
**Status**: Contested — owner rerouted the missing Claude verdict to Grok, but
Grok authentication failed before review
**Branch**: `main`
**Commit**: `81d5497`

## Evidence

- `PlexLibrary::transcode_decision` constructs the universal decision query by
  hand.
- `PlexLibrary::transcode_url` separately constructs the matching `start.m3u8`
  query.
- `PlexLibrary::direct_flags` shares only the delivery-flag values. Its current
  guard does not capture the production decision request or compare the full
  query contract.
- Finding `or-7` records that the two builders previously drifted on
  `directStream`, so the decision could approve a delivery the start URL would
  not request.
- `.agents/review/findings/tr-11.md` records a second live-only failure caused
  by both hand-built queries omitting the same required profile selector. The
  `tr-11` repair shares the value through a constant but still inserts the
  query pair separately.

Trigger: a later universal-transcode change adds or changes a common parameter
in only one builder.

## Predicted observable failure

Plex approves one parameter set during `decision`, then receives a materially
different `start.m3u8` request. Capability guards for an individual key can
remain green while the real server refuses the start or produces a different
delivery.

## What

The common request contract is duplicated rather than represented once with
explicit decision/start differences. Two independent drift failures make this
a demonstrated maintenance risk rather than a style preference.

## Approach

Revision 1 landed in
`.agents/plans/tr-13-plex-universal-query-builder.md`: one private typed query
builder now represents the common contract, with delivery, offset, session,
and client-identity differences explicit. The post-`tr-10` credential boundary
is preserved by keeping the builder token-blind. Both production callers are
guarded through real wire output, with a separate source guard proving the
query vector is no longer duplicated.
