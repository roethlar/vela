# tr-11: Plex transcode requests omit the required client profile

**Severity**: HIGH — real Plex conversion is unavailable: the quality menu
offers Original only, so explicit tiers and Automatic cannot start.
**Status**: Open — live root cause proven 2026-07-26; fix not started
**Branch**: (not started)
**Commit**: (none)

## Evidence

`npm run e2e:live live-transcode` ran against commit `85248d9` (1.0.54) and
failed before playback: every one of its first 12 movie candidates returned no
convertible tier.

All 12 candidates were otherwise eligible for the gentlest tier. Their real
`/video/:/transcode/universal/decision` requests returned 400. The Plex server
log named the cause on every request:

```
Unable to find client profile for device; platform=, platformVersion=, device=, model=
TranscodeUniversalRequest: unable to find a matching profile
```

`PlexLibrary::transcode_decision` builds no
`X-Plex-Client-Profile-Name` query parameter. `PlexLibrary::transcode_url`
omits it from the corresponding `start.m3u8` request as well.

A one-variable live probe proves causation:

- the production decision query returned 400;
- the same query with `X-Plex-Client-Profile-Name=Web` returned 200,
  `generalDecisionCode=1001`, “Direct play not available; Conversion OK”; and
- the matching `start.m3u8` request returned a usable master and child playlist,
  followed by a 206 segment response.

The server's installed `Web` profile supports HLS. Several other installed HLS
profiles also returned Conversion OK; `Plex Desktop` returned a valid decision
but no conversion because that profile targets HTTP rather than HLS.

## Predicted observable failure

On the owner's Plex, every version's `quality_options` response contains no
tiers even when its media is convertible. The frontend therefore cannot offer
“Play at Quality,” and a saved non-Original quality cannot reach a working
transcode. The live scenario fails at its candidate-selection assertion and
never launches mpv.

## What

The feature's provider contract requires a Plex client profile for universal
transcoding. The implementation copied the media, tier, and session parameters
but not the profile selector used to choose the HLS transcode target. Unit mocks
accepted the incomplete request, so all local verification passed while the
real server rejected it.

## Approach

(not started — code work requires an approved plan)

Choose and document the HLS client profile Vela will present, then send that
same `X-Plex-Client-Profile-Name` on both the decision and `start.m3u8`
requests. Keep both builders aligned with one helper or one guarded constant.
The live-proven `Web` profile is the smallest known working value.

Guard both query builders, red-prove each independently, then run
`npm run e2e:live live-transcode` to prove a tier is offered, Plex opens the
session, and Vela closes it. Correct the scenario file's stale leading command
comment (`transcode` → `live-transcode`) in the same test change.
