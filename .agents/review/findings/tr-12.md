# tr-12: Plex decision failures are silently collapsed

**Severity**: MEDIUM — a server/profile incompatibility can remove every
convertible tier and force Original with no actionable client-side diagnostic.
**Status**: In progress — implementation verified; Claude review pending
**Branch**: `main`
**Commit**: `9cde6b2`

## Evidence

- `src-tauri/src/source/plex.rs:1301-1305` creates a decision session id, awaits
  `transcode_decision`, then collapses every request, status, and parse error to
  `false` with `.unwrap_or(false)`.
- `src-tauri/src/source/plex.rs:1431-1439` does the same immediately before an
  explicit-tier play.
- `src-tauri/src/source/plex.rs:1448-1458` logs only the generic
  “conversion unavailable for this copy; playing the original” fallback.
- `.agents/review/findings/tr-11.md` records that the missing profile was
  diagnosable only from Plex's server log. The live-proven `Web` profile is
  verified on one installation, not across Plex versions or installations.

Trigger: a Plex installation lacks a profile literally named `Web`, rejects
the decision request for another protocol reason, or returns an unreadable
decision response.

## Predicted observable failure

Every decision returns an error, `quality_options` offers Original only, and an
explicit tier falls back to Original. Vela's log does not distinguish a request
failure from a legitimate “Conversion not available” decision, so the user or
operator must inspect the Plex server log to find the cause.

## What

The capability boundary converts transport, HTTP-status, and response-parse
failures into the same boolean as a valid server refusal. That fail-closed
behavior is safe for playback but leaves the failure unactionable and can hide
a recurrence of `tr-11` on another server.

## Approach

`9cde6b2` adds a payload-free `PlexDecisionError`, classifies every decision
response stage before XML parsing, rejects a response with no decision code,
and preserves valid negative decisions as ordinary refusals. The quality-menu
caller propagates the safe error into its existing inline alert; the explicit
tier caller logs that same safe reason once and retains the Original fallback.
The implementation also adds Rust boundary/caller guards, a source-wiring
guard, and a real-app mock-Plex scenario without refactoring the separately
gated `tr-13` query builders.

## Guard proof

Every planned behavior was mutated independently against committed
`9cde6b2`, failed for the intended reason, and was restored to a clean tree:

- bypassing the non-success status return made
  `plex_decision_http_error_is_sanitized` fail because HTTP 503 became a valid
  refusal;
- routing transport failure through raw reqwest text made
  `plex_decision_transport_error_is_sanitized` fail with synthetic request
  context present;
- collapsing malformed XML to a default decision made
  `plex_decision_malformed_body_is_sanitized` fail;
- removing only the missing-code validation made
  `plex_decision_missing_code_is_invalid` fail;
- treating every non-1xxx code as invalid made
  `plex_decision_valid_refusal_is_quiet` fail;
- collapsing only `playback_options` errors made both failure-path options
  guards and the Node wiring guard fail while the valid-refusal guard stayed
  green; the same mutation made Linux `plexdecision` fail 0/1 waiting for the
  inline alert;
- collapsing only the explicit-tier caller and removing its safe diagnostic
  made the Node reporting-wiring guard fail; and
- after every restoration, the worktree was clean. The final targeted rerun
  passed 5/5 decision guards, 3/3 options guards, 1/1 fallback guard, and the
  Node wiring guard 1/1.

Complete local verification passed: exact JS toolchain, `npm ci`, `npm audit`
with zero vulnerabilities, frontend check/build, Rust 1.89 and stable checks,
clippy with warnings denied, all 360 Rust tests, and Cargo audit with only the
existing unmaintained/unsoundness notices. Exact committed Linux verification
passed focused `plexdecision` 1/1 and the full suite 39/39; the focused
screenshot shows the complete inline diagnostic without overflow. Real-Plex
`live-transcode` passed 1/1: decision probes created no fresh session, the play
opened its own session, and teardown removed it. Post-run, the VM was clean at
`9cde6b2`, no mpv process/listener or credentials file remained, and Plex plus
its watchdog were active.
